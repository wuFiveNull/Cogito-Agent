# 仓库指南

## 项目目的

Cogito-Agent 是一个本地优先的个人 Agent Runtime，具备长期记忆、受治理的能力调用、可追踪执行、可复用 Skill，以及受限制的主动行为。

## 当前优先级

先完成 MVP。MVP 必须小、可运行、可测试，并且只在本地运行：CLI 聊天、一个模型适配器、最小存储、基础记忆/上下文检索、策略检查、能力注册表、Trace/Audit 日志，以及一个端到端演示。

## Codex 在本仓库中的工作方式

实现前先阅读 `docs/01_PROJECT_SPEC.md` 到 `docs/06_IMPLEMENTATION_BACKLOG.md`。所有代码变更必须遵循这些文档。如果文档冲突，产品范围以编号更小的规格为准，实现细节以更具体的规格为准。

## Codex 可以修改什么

Codex 可以修改完成当前任务所需的源码、测试、文档、配置和本地脚本。变更必须保持小范围。如果实现中产生了具体决策，需要更新相关规格或 backlog。

## Codex 不得过度建设

MVP 阶段不要实现云同步、插件市场、分布式队列、多 Agent 编排、UI 客户端、主动通知或完整 Skill 自动化，除非 backlog 明确提升这些事项的优先级。不要在确实需要之前引入框架。

## 仓库规则

保持清晰的模块边界。Runtime 编排不得直接依赖具体模型提供方、工具实现、存储驱动或 UI 渠道。能力调用必须经过策略、Trace 和 Audit 路径。敏感数据不得提交。

## 私有与排除目录

除非用户在当前任务中明确要求，Codex 不得读取、修改、总结或引用 `docs_zh/`、`private/`、`.local/` 或 `secrets/` 下的文件。这些路径由 `.gitignore` 排除版本控制。

## 质量要求

每个行为变更都要配套测试。Python 项目配置存在后，优先使用 `pytest`、Ruff 和 mypy。新的公共函数应提供类型标注。安全、审批、审计和删除行为需要负向测试。

## 完成定义

当代码、测试、文档和 backlog 状态一致；本地 demo 或相关测试路径可运行；适用场景下 Trace/Audit 行为可见；并且 MVP 范围没有在未更新文档的情况下扩大时，任务才算完成。
