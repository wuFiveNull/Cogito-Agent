# Cogito-Agent 本地优先个人 Agent Runtime 开发执行总文档

## 0. 文档用途

你现在要根据本文档，逐步开发 Cogito-Agent。

Cogito-Agent 的目标不是做一个普通聊天机器人，而是做一个**本地优先、单用户、可追溯、可控权限、具备长期记忆和可扩展能力的个人 Agent Runtime**。

当前阶段不要追求完整终局架构。第一目标是做出一个能真实运行、能测试、能审计、能继续扩展的 MVP。

你必须遵守本文档的阶段边界，不允许提前堆复杂功能。

---

# 1. 总体目标

## 1.1 产品目标

构建一个本地优先的个人 Agent Runtime，具备以下长期目标：

1. 单用户本地运行。
2. 支持基础对话。
3. 支持少量安全工具调用。
4. 支持最小长期记忆。
5. 支持权限治理。
6. 支持 Trace 与 Audit。
7. 支持未来扩展 Skill、MCP、Plugin、Subagent。
8. 支持未来主动任务和多工作区。

## 1.2 MVP 目标

MVP 只做以下能力：

1. 单用户。
2. 本地优先。
3. 单入口，优先 CLI。
4. 能完成基础对话。
5. 能安全读取 workspace 内文件。
6. 能在用户审批后写入 note 文件。
7. 能生成 MemoryCandidate。
8. 能由用户确认后写入长期记忆。
9. 每轮对话都有 trace_id。
10. 工具调用、模型调用、权限判断、记忆变更都可追溯。
11. 所有高风险操作默认拒绝或要求审批。
12. 有自动化测试。

## 1.3 MVP 明确不做

第一版不要做：

1. 多 Agent 工作区。
2. Subagent。
3. Skill Runtime。
4. Plugin Marketplace。
5. MCP 任意接入。
6. Telegram、飞书、微信、Discord 等多入口。
7. 主动服务。
8. Drift Runtime。
9. 自主后台任务。
10. Shell 执行。
11. 浏览器自动化。
12. 邮件发送。
13. 日历修改。
14. 多用户。
15. 云同步。
16. 分布式任务系统。
17. 复杂 Web Dashboard。

# 2. 技术原则

## 2.1 Runtime Kernel 最小化

Runtime Kernel 只负责：

1. Turn 状态推进。
2. 调度 Context Builder。
3. 调度 Model Client。
4. 调度 Capability Registry。
5. 调度 Policy Engine。
6. 调度 Trace Sink。
7. 控制预算、重试、中断和失败状态。

Runtime Kernel 不允许直接绑定：

1. 具体模型供应商。
2. 具体工具实现。
3. 具体数据库实现。
4. 具体 UI。
5. 具体 Skill。
6. 具体插件。

所有外部依赖必须通过 interface / port 调用。

## 2.2 默认安全

默认规则：

1. 未声明权限的 capability 默认 deny。
2. Shell 默认 deny。
3. Workspace 外文件访问默认 deny。
4. 文件写入默认 require_approval。
5. 网络访问默认 require_approval 或 deny。
6. Secret 永远不能进入 prompt、trace 明文或 audit 明文。
7. 外部内容默认 untrusted。
8. Memory 写入默认 pending，不自动进入长期记忆。

## 2.3 本地优先

MVP 默认所有数据保存在本地：

1. SQLite 保存状态、会话、消息、trace、audit、memory。
2. Workspace 文件保存在本地目录。
3. Secret 使用系统环境变量或本地 secret ref。
4. 不做云同步。
5. 模型可以调用远程 API，但必须在配置中明确标记。

## 2.4 可测试优先

必须从第一天支持：

1. Mock Model。
2. Mock Capability。
3. Policy 单元测试。
4. State Machine 单元测试。
5. Golden Replay 测试。
6. SQLite migration 测试。

# 3. 推荐技术栈

如果没有额外限制，优先使用：

```text
Language: Python 3.11+
Package Manager: uv 或 poetry
CLI: Typer 或 Click
DB: SQLite
Migration: Alembic 或自定义 migration runner
Schema: Pydantic v2
Testing: pytest
Lint/Format: ruff
Type Check: mypy 或 pyright
Config: YAML + env
Model API: OpenAI-compatible interface
```

MVP 不要引入：

1. Kubernetes。
2. 微服务。
3. Kafka。
4. Temporal。
5. Redis。
6. 多进程 worker。
7. 重型 Web 框架。
8. LangChain 全家桶式耦合。

# 6. 核心数据模型

所有 schema 使用 Pydantic 定义。字段名保持稳定，后续数据库表与 API 都按这些 schema 演进。

## 6.1 RuntimeEvent

```python
class RuntimeEvent(BaseModel):
    id: str
    trace_id: str | None = None
    session_id: str | None = None
    turn_id: str | None = None
    type: Literal[
        "user_message",
        "tool_intent",
        "approval_result",
        "timer",
        "system"
    ]
    actor: Literal[
        "user",
        "agent",
        "skill",
        "scheduler",
        "system"
    ]
    payload_redacted: dict = Field(default_factory=dict)
    payload_ref: str | None = None
    created_at: datetime
```

字段解释：

1. `id`：事件 ID。
2. `trace_id`：所属 Trace。
3. `session_id`：所属会话。
4. `turn_id`：所属 Turn。
5. `type`：事件类型。
6. `actor`：触发主体。
7. `payload_redacted`：脱敏 payload。
8. `payload_ref`：大 payload 引用。
9. `created_at`：创建时间。

## 8.1 状态列表

```text

waiting_approval

```

## 8.2 状态转移

```text
received
  -> loading_session
  -> building_context
  -> model_calling
      -> composing_result
      -> planning_tool
          -> policy_checking
              -> executing_capability
              -> waiting_approval
              -> model_calling
          -> updating_context
          -> model_calling
  -> extracting_memory
  -> completed
```

任意状态可以转移到：

```text
failed
cancelled
budget_exceeded
```

## 8.3 Kernel 主循环伪代码

```python
class RuntimeKernel:
    def run_turn(self, event: RuntimeEvent) -> TurnResult:
        trace = self.tracer.start_trace(event)
        turn = self.create_turn(event, trace)

        try:
            self.set_status(turn, "loading_session")
            session = self.session_store.load_or_create(event.session_id)

            self.set_status(turn, "building_context")
            context = self.context_builder.build(session=session, event=event)

            while True:
                self.check_budget(turn)

                self.set_status(turn, "model_calling")
                model_result = self.model_client.call(context)

                self.record_model_call(trace, model_result)

                if model_result.has_tool_call:
                    self.set_status(turn, "planning_tool")
                    call = self.capability_registry.plan_call(model_result.tool_call)

                    self.set_status(turn, "policy_checking")
                    decision = self.policy_engine.decide(call)

                    self.record_policy_decision(decision)

                    if decision.decision == "deny":
                        context.add_system_tool_denied(call, decision)
                        continue

                    if decision.decision == "require_approval":
                        self.set_status(turn, "waiting_approval")
                        approval = self.approval_manager.request(decision, call)

                        if not approval.is_approved:
                            context.add_user_rejected_tool(call, approval)
                            continue

                    self.set_status(turn, "executing_capability")
                    tool_result = self.capability_registry.execute(call)

                    self.record_tool_result(tool_result)

                    self.set_status(turn, "updating_context")
                    context.add_tool_result(tool_result)
                    continue

                self.set_status(turn, "composing_result")
                final = self.result_composer.compose(model_result, context)

                self.message_store.save_assistant_message(session.id, turn.id, final.content)

                self.set_status(turn, "extracting_memory")
                self.memory_candidate_service.extract_from_turn(session, turn, final)

                self.set_status(turn, "completed")
                self.tracer.finish_trace(trace, status="succeeded")
                return final

        except BudgetExceeded as e:
            self.set_status(turn, "budget_exceeded", error=str(e))
            self.tracer.finish_trace(trace, status="failed")
            return TurnResult(content="本轮已达到预算限制，我只能基于已有信息回答。")

        except Exception as e:
            self.set_status(turn, "failed", error=str(e))
            self.tracer.finish_trace(trace, status="failed")
            raise
```

## 8.4 Budget 控制

每轮限制：

1. 最大状态步数：12。
2. 最大模型调用：4。
3. 最大工具调用：5。
4. 最大上下文 token：24000。
5. 最大输出 token：4000。
6. 最大耗时：120 秒。

超限后：

1. 停止继续调用工具。
2. 不再请求新模型规划。
3. 让模型基于已有信息生成最终回复。
4. Trace 中记录 `budget_exceeded`。

## 8.5 Retry 规则

| 对象                   | Retry 规则               |
| -------------------- | ---------------------- |
| Model call           | timeout / 429 最多重试 2 次 |
| Tool schema repair   | 最多让模型修复 1 次            |
| Read-only capability | 最多重试 1 次               |
| Write capability     | 默认不自动重试                |
| Policy engine        | 失败即 deny               |
| Approval             | 过期即 reject             |

4. 用户明确给出偏好。
5. 用户明确给出待办。

# 19. 安全要求

## 19.1 Secret

禁止：

1. Secret 出现在 prompt 明文。
2. Secret 出现在 trace 明文。
3. Secret 出现在 audit 明文。
4. Secret 出现在工具输出。
5. 模型读取 secret value。

允许：

1. Executor 使用 secret_ref。
2. Audit 记录 secret access metadata。
3. Config 引用 secret_ref。

## 19.2 Prompt Injection

必须实现：

1. 外部内容 untrusted 标记。
2. 外部内容不能作为 instruction。
3. 工具结果进入 prompt 前包装。
4. 模型不应根据外部内容扩大权限。
5. Memory 不从外部内容直接写入。

## 19.3 文件安全

必须实现：

1. Workspace root 限制。
2. Canonical path。
3. Symlink escape 检测。
4. 写文件 diff。
5. 写文件 approval。
6. 大文件截断。
7. 禁止访问 secret 目录。

## 19.4 Shell

MVP 禁止 shell。

如果用户要求添加 shell，必须拒绝实现，直到 Phase 3 后引入 sandbox 设计。
